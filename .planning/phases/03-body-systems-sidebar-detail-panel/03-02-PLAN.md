Update `src/body-map-explorer.ts` to own the shared Phase 03 state:

```typescript
@state() private activeSystemId: BodySystemId | null = null;
@state() private selectedOrganIds: string[] = [];
```

Also add these derived helpers:

```typescript
private get activeSystem(): BodySystemDefinition | null
private get systemHighlightOrganIds(): string[]
```

`systemHighlightOrganIds` must return `this.activeSystem?.organIds ?? []`. Do not merge system highlights into `selectedOrganIds`; SYSTEM-05 depends on keeping those buckets separate.

Replace the placeholder left and right panel markup with:

```html
<body-map-sidebar
  .systems=${BODY_SYSTEMS}
  .activeSystemId=${this.activeSystemId}
  @system-toggle-request=${this._handleSystemToggleRequest}
></body-map-sidebar>

<body-map-model
  .selectedOrganIds=${this.selectedOrganIds}
  .systemHighlightOrganIds=${this.systemHighlightOrganIds}
></body-map-model>

<body-map-detail-panel
  .system=${this.activeSystem}
></body-map-detail-panel>
```

Implement `_handleSystemToggleRequest(event: CustomEvent<{ systemId: BodySystemId }>)` with exact toggle behavior:

- if `event.detail.systemId === this.activeSystemId`, set `this.activeSystemId = null`
- otherwise set `this.activeSystemId = event.detail.systemId`

Implement `_handleOrganSelectionChange(event: CustomEvent<{ selectedOrganIds: string[]; lastToggled: string; isSelected: boolean }>)` with these rules:

1. set `this.selectedOrganIds = event.detail.selectedOrganIds`
2. look up `const mappedSystemIds = ORGAN_TO_SYSTEM[event.detail.lastToggled] ?? []`
3. on selection (`isSelected === true`), set `this.activeSystemId = mappedSystemIds[0] ?? this.activeSystemId`
4. on deselection, if the current `activeSystemId` is in `mappedSystemIds` and none of `this.selectedOrganIds` belong to `this.activeSystem?.organIds`, clear `this.activeSystemId`

That `mappedSystemIds[0]` rule is deliberate: it keeps the first-match behavior from the legacy implementation, so `thymus` activates `endocrine` before `immune`, and `knee_joint` activates `muscular` before `skeletal`.

Create `src/__tests__/body-map-explorer.test.ts` that mounts the real explorer component and asserts the three behaviors above by querying the child custom elements and dispatching actual custom events. The deselection assertions must check both data flow and UI restoration:

- after sidebar re-toggle, `detail.system` is `null` and the empty-state copy `Select a body system to see details.` renders again
- after organ-driven deselection clears the active system, `detail.system` is `null` and the same empty-state copy renders again

After the tests pass, run `npm run build` so the new imports and generated bundle are verified together.
