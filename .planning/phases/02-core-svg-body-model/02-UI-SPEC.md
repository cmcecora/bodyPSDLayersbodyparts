## Interaction States

This phase is primarily an interaction contract. Three distinct visual themes apply per view mode.

### Organs View (blue theme)

| State            | Hit-Area Fill               | Image Filter                                   |
| ---------------- | --------------------------- | ---------------------------------------------- |
| Default          | `transparent`               | none                                           |
| Hover            | `rgba(100, 180, 255, 0.35)` | `drop-shadow(0 0 6px rgba(66, 165, 245, 0.7))` |
| Selected         | `rgba(66, 145, 230, 0.45)`  | `drop-shadow(0 0 6px rgba(66, 165, 245, 0.7))` |
| Selected + Hover | `rgba(66, 145, 230, 0.55)`  | `drop-shadow(0 0 6px rgba(66, 165, 245, 0.7))` |

Transition: `fill 0.2s ease, opacity 0.2s ease` on hit-area; no transition on filter.

### Organs 2 View (blue theme — same as Organs)

Organs2 view uses the same `.body-part-group.selected` class as the organs view. Hover and selection highlight colors are identical to the organs view (blue theme). The purple color (`#9b59b6`) applies only to the "Organs 2" tab button's active state, not to organ highlights.

Organs2 behavior difference: clicking an organ adds `.selected` class transiently while the modal is open (Phase 4 concern), not as a persistent toggle. Phase 2 must only apply the highlight CSS class — modal wiring is out of scope.

### Body Sections View (green theme)

| State            | Hit-Area Fill               |
| ---------------- | --------------------------- |
| Default          | `transparent`               |
| Hover            | `rgba(76, 175, 80, 0.35)`   |
| Selected         | `rgba(144, 238, 144, 0.45)` |
| Selected + Hover | `rgba(144, 238, 144, 0.55)` |

No drop-shadow filter applied to section hit-areas. Transition: `fill 0.2s ease, opacity 0.2s ease`.

Body Parts highlight ellipses (overlaid on sections view when a body part is active): `fill: rgba(76, 175, 80, 0.3)`, `stroke: rgba(76, 175, 80, 0.55)`, `stroke-width: 2`, `filter: url(#bp-glow)`. Hover state: `fill: rgba(76, 175, 80, 0.5)`, `stroke: rgba(76, 175, 80, 0.8)`.

### SVG Filter Definitions

Two named SVG filters must be declared in `<defs>`:

- `#blue-glow`: `<feDropShadow dx="0" dy="0" stdDeviation="4" flood-color="#42a5f5" flood-opacity="0.6">`
- `#green-glow`: `<feDropShadow dx="0" dy="0" stdDeviation="4" flood-color="#4caf50" flood-opacity="0.6">`

### Layer Crossfade

SVG layers (`#organs-layer`, `#sections-layer`, `#back-sections-layer`, `#bp-highlight-layer`) transition opacity with `0.35s ease-in-out` when switching views.

## Component Structure

The `<body-map-model>` Lit component wraps:

1. View-switcher tabs (above)
2. SVG wrapper containing the layered SVG body model
3. Gender toggle (below)

SVG layer IDs to preserve for cross-phase compatibility:

- `#organs-layer` — 20 organ `<g class="body-part-group">` elements
- `#organs2-layer` — same organ groups in organs2 mode
- `#sections-layer` — 14 section `<g class="body-section-group">` elements
- `#bp-highlight-layer` — ellipse overlays for body-parts view

Organ group ID pattern: `group-{part_id}` (e.g., `group-brain`, `group-heart`).
Data attributes: `data-part="{snake_case_id}"`, `data-name="{Human Readable Name}"`.

Organ images: loaded from `public/assets/organs/{part_id}.webp` via URL reference (never base64 inline, per BUILD-02/MODEL-07 and PITFALLS.md). All 19 images load eagerly on component mount (D-09).

---

## Image Loading

All organ images load on component mount. No lazy loading.

Source: `public/assets/organs/*.webp` (19 files confirmed in Phase 1).

`assetsInlineLimit: 0` in `vite.config.ts` prevents Vite from inlining images as base64. Images must be referenced as URL strings, not imported as modules.

## Entrance Animations

Claude's discretion area (from CONTEXT.md). Decision: replicate the existing fade-slide animation.

The existing app applies `.animate-fade-slide` to `.view-toggle` on DOM ready (line 7006). Phase 2 should apply a matching entrance animation on first render using Lit's `firstUpdated()` lifecycle hook. Animation: `opacity 0 → 1` + `translateY(8px) → 0` over `0.4s ease-out`. This preserves visual continuity with the legacy app without being a hard contract requirement.

If implementation complexity arises, skip the animation — it is a Phase 2 discretion item, not a MODEL requirement.
