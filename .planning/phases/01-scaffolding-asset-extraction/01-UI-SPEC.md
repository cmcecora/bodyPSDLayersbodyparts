## Spacing Scale

Declared values (must be multiples of 4). Phase 1 renders minimal UI — this scale is declared as the carry-forward target for Phase 2+ normalization. Source: 8-point scale standard; consistent with spacing observed in existing monolith CSS.

| Token | Value | Usage                     |
| ----- | ----- | ------------------------- |
| xs    | 4px   | Icon gaps, inline padding |
| sm    | 8px   | Compact element spacing   |
| md    | 16px  | Default element spacing   |
| lg    | 24px  | Section padding           |
| xl    | 32px  | Layout gaps               |
| 2xl   | 48px  | Major section breaks      |
| 3xl   | 64px  | Page-level spacing        |

Exceptions: none for Phase 1. Touch target minimum of 44px applies starting Phase 2 (MODEL-02, MODEL-03).

## Color

Source: Existing monolith color system (CLAUDE.md § CSS Conventions > Color System). These are existing values, not redesigned choices. Phase 1 codifies them as CSS custom properties so Phase 2+ can reference `--bme-*` tokens instead of raw hex.

| Role            | Value     | Usage                                                                     |
| --------------- | --------- | ------------------------------------------------------------------------- |
| Dominant (60%)  | `#f5f5f5` | Page background (source: existing `.page-layout` background)              |
| Secondary (30%) | `#ffffff` | Panel surfaces — cards, sidebar, nav (source: existing panel backgrounds) |
| Accent (10%)    | `#6cb5f4` | Border highlights, selected-state indicators only                         |
| Header surface  | `#434448` | Panel/sidebar header backgrounds with `#ffffff` text                      |
| Destructive     | `#dc2626` | Destructive actions only (not present in Phase 1; declared for Phase 4+)  |

Accent reserved for: organ selected-state border, active system indicator dot border, focused interactive element outline. Never used for body text, general borders, or decorative elements.

Body system colors (carry-forward from `BODY_SYSTEMS` array — used in Phase 3):

| System         | Color                              |
| -------------- | ---------------------------------- |
| Cardiovascular | `#e87722`                          |
| Others         | Defined in BODY_SYSTEMS data array |

CSS custom properties to be declared in Phase 1 component shell:

```css
--bme-surface: #f5f5f5;
--bme-panel: #ffffff;
--bme-header-bg: #434448;
--bme-header-text: #ffffff;
--bme-accent: #6cb5f4;
--bme-hover-overlay: rgba(100, 180, 255, 0.35);
--bme-border: #e0e0e0;
--bme-divider: #f0f0f0;
--bme-destructive: #dc2626;
```

## Asset Organization Contract

Source: CONTEXT.md decisions D-02, D-03, D-04. This is the primary deliverable contract for Phase 1.

| Directory                   | Contents                                                        | Count | Format |
| --------------------------- | --------------------------------------------------------------- | ----- | ------ |
| `public/assets/organs/`     | Organ layer images extracted from base64 in HTML `<image>` tags | 66    | WebP   |
| `public/assets/body-parts/` | Body part thumbnails converted from `bpart_images/`             | 77    | WebP   |
| `public/assets/systems/`    | Body system overview images converted from `bodyimage/`         | 12    | WebP   |

**Rules:**

- Zero base64 strings remain in HTML or JS source after Phase 1 (BUILD-02, BUILD-03)
- All images land in Vite's `public/` directory — never bundled into JS output (CONTEXT.md D-04, PITFALLS.md)
- All PNGs converted to WebP — no PNG files in the deliverable
- Data files convert from `window.*` JS globals to JSON in `public/data/` (CONTEXT.md D-05, D-06):
  - `public/data/diseases.json` (~7.3 MB)
  - `public/data/symptoms.json` (~429 KB)
  - `public/data/symptoms-by-part.json` (~99 KB)

## Phase 1 Component Shell Scope

Source: CONTEXT.md D-01 (Claude's discretion).

The Phase 1 shell must:

1. Prove `npm run dev` starts a hot-reloading dev server
2. Prove `npm run build` outputs a Web Component bundle under 500 KB
3. Prove at least one external WebP image loads correctly (validating the asset pipeline)
4. Declare CSS custom properties (`--bme-*` tokens) in the component's Shadow DOM stylesheet
5. Export a minimal `<body-map-explorer>` custom element that renders a placeholder layout matching the three-column structure (left sidebar placeholder, center body model placeholder, right panel placeholder)

The shell does NOT render any interactive organs, sidebar data, or panel content — those belong to Phases 2–4.
